# Восстановление MIDI без перезагрузки Windows

[English](MIDI_RECOVERY.en.md)

## FocGrain 1.0.4 и новее

1. Сохраните работу в DAW и других MIDI-программах: перезапуск общей службы временно разорвёт их MIDI-соединения.
2. В меню трея FocGrain выберите **«Восстановить MIDI без перезагрузки…»**.
3. Прочитайте подтверждение и разрешите UAC. При отмене UAC служба не изменяется.
4. Старый FocGrain закроется. Одноразовый помощник дождётся его выхода, получит блокировку единственного MIDI-владельца и перезапустит только **midisrv**.
5. Если обычная остановка службы зависла, помощник проверит точный путь **System32\MidiSrv.exe**, состояние Stop Pending и единоличное владение процессом. Только затем разрешено завершение этого процесса. Общий или изменившийся процесс завершаться не будет.
6. После успешного восстановления FocGrain автоматически запускается снова с обычными правами, создаёт порт и проверяет WinMM. Команды gain при восстановлении не отправляются. При необходимости заново откройте список MIDI в FC2 и выберите FocGrain, канал 1 / All channels, Enable pickup выключен.

Никакая дополнительная постоянно работающая служба не устанавливается. FC2, драйвер Focusrite, аппаратные настройки и остальные службы не завершаются помощником. У него нет параметра произвольного имени службы, PID для завершения или пути исполняемой программы. Сервис восстанавливается только после явного подтверждения, не по таймеру и не при обычном старте.

## Обновление и удаление

Новая версия возвращает код **31**, если MIDI не закрылся корректно, и сохраняет диагностическую отметку в профиле пользователя. Она очищается после успешного восстановления службы или готовности нового MIDI-входа. Временный помощник установки также считает версии до 1.0.4 требующими проверки: они не сообщали результат native cleanup.

Если закрытие неполное, интерактивный установщик предлагает восстановить MIDI-службу перед продолжением. При отказе обновление останавливается до записи файлов/запуска новой копии. Тихая установка службу не перезапускает и в этом случае отказывается от обновления. При удалении можно отказаться от восстановления и всё равно удалить приложение: общая служба не изменяется без согласия.

Это контролируемый обход системного зависания, а не изменение реализации Windows MIDI Services. При отказе по правам, изменившемся процессе или ошибке восстановления смотрите application.log. Полная перезагрузка Windows остаётся резервным вариантом, а не первым шагом.

## Что подтверждено диагностикой

26 октября у устройства FocGrain оставалась APPDEV-запись OK, но не было входа WinMM. Удаление только этой программной записи не помогло. После согласованного перезапуска midisrv появилась ровно одна рабочая запись WinMM FocGrain. Подробности и версии — в [AUDIT.md](AUDIT.md) и [TESTED_SETUP.md](TESTED_SETUP.md).

Идентификатор Windows-устройства строится из постоянного ProductInstanceId; меняющийся AssociationId сам по себе не доказывает смену идентификатора устройства. Список без открытия портов: scripts/Inspect-MidiPorts.ps1 из исходников.

Microsoft описывает похожий дефект виртуального транспорта: [#1047](https://github.com/microsoft/MIDI/issues/1047), [комментарий разработчика от 21 октября](https://github.com/microsoft/MIDI/issues/819). Приложение не подменяет компоненты Windows и не удаляет обновления безопасности.

Сам встроенный помощник 1.0.4 проверен на этом ПК 26 октября: закрытие старой копии вернуло 31, восстановление — 0, служба стала Running, отметка сбоя очищена. Обычная копия затем создала ровно один вход WinMM FocGrain. Перезагрузка Windows и gain-команды для проверки не использовались.
